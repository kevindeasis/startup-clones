# Build spec — Kairos Health clone ("ChairFill": AI front desk for a dental practice)

**Original:** Kairos Health (YC F26) — https://kairoshealthai.com · YC page: https://www.ycombinator.com/companies/kairos-health
**Product (from public pages):** "AI front desk that fills every chair for dental practices." It plugs into the practice-management system (Open Dental, Dentrix, Eaglesoft…), answers every inbound patient call 24/7 (scheduling, rescheduling, patient intake, insurance questions), verifies insurance benefits in seconds, and runs **outbound recall**: it finds patients overdue for care and calls/texts them to book directly into open slots. It also shows analytics on calls, bookings and follow-ups.
**Clone name:** `chairfill`. Single practice, self-hosted, no auth. Everything (patients, payers, practice) is fictional. **Text-first**: the "phone call" is a chat transcript; voice is an optional browser-only layer (Web Speech API) with no server audio. No real PMS integration — SQLite is the "practice management system".

## Core flows (all required)

1. **Inbound AI receptionist (chat = simulated call/SMS).** Page `/` with a chat panel labelled as a call to the practice. The agent: greets, identifies the patient (full name + date of birth; if unknown, offers to register as a new patient with name, DOB, phone), finds the reason for the visit (cleaning/hygiene, exam, emergency/toothache, follow-up), checks real availability and **offers at most 3 concrete slots**, confirms the choice back before booking, books it, and reads back the confirmation (date, time, provider, chair). Also handles: reschedule and cancel of an existing appointment, FAQ answers from the practice profile (hours, address, parking, accepted insurers, what to bring), insurance questions (flow 3), and "take a message" when the request needs a human (billing dispute, clinical advice, complaint). Never give clinical advice. Every tool call the agent made is listed under the reply (name + arguments + result) so the demo shows the agent acting on the schedule. Conversation ends with an **outcome**: `booked | rescheduled | cancelled | insurance_verified | faq | message_taken | abandoned`.
   - Optional voice toggle: use the browser `SpeechRecognition` (webkit) API for input and `speechSynthesis` for output; degrade silently if unsupported.
2. **Outbound recall campaign ("fill every chair").** Page `/recall`. "Overdue" = last completed hygiene/exam appointment more than `RECALL_MONTHS` (default 6) months before today AND no future appointment. Button **Run recall** → for each overdue patient, the agent writes a short personalised SMS-style outreach (first name, how long since last visit, their usual hygienist if known, 2 proposed open slots in the next 14 days, opt-out line) and stores it as `recall_outreach` with status `sent`. Each outreach row has a **Simulate reply** box: the user types what the patient would text back ("Tuesday works", "call me next month", "I moved") and the same receptionist agent (channel `recall`) continues the thread, books into a slot when the patient agrees, or marks `declined` / `snoozed`. Dashboard counters: overdue patients, outreach sent, replies, booked from recall.
3. **Insurance verification.** Tool `verify_insurance(payer, member_id, dob)` looks up a **mock payer directory** in SQLite (fictional payers: "Delta Mutual", "Aetnor", "BlueCrest", "Medicaid-Demo", each with eligibility rules). Returns: eligible yes/no, plan name, in-network yes/no, annual maximum, remaining maximum, coverage % for preventive/basic/major, copay notes, and `flags` (inactive member, out of network, remaining max below $200, waiting period). The agent explains the result in plain language (no promises about exact cost). Verification results are stored on the patient's `insurance_plans` row with `verified_at`. Also exposed on a small form on `/insurance` so staff can verify without a call.
4. **Schedule dashboard.** Page `/schedule?date=YYYY-MM-DD` (default today) showing a grid of operatories ("chairs", 4 of them) × 30-minute slots across practice hours. Booked slots show patient initials, type, provider; AI-made bookings (source `ai_inbound` / `ai_recall`) are visually tagged. Header shows **chair utilisation %** for the day and the week, and arrows for prev/next day. Double-booking of a chair or provider must be impossible at the DB layer (check on insert; return a clear error that the agent relays by offering other slots).
5. **Calls & analytics.** Page `/calls`: list of conversations (channel, patient, started, outcome, # turns, mock/real badge) with a transcript drawer, plus counters for the last 30 days: calls handled, appointments booked by AI, reschedules, insurance verifications, messages taken, recall outreach sent / booked. Also a `/messages` list of messages taken for staff (patient, phone, summary, created_at, done checkbox).

## Stack
Python 3.11+, **FastAPI + Uvicorn**, SQLite via stdlib `sqlite3` (no ORM), **Jinja2** templates + vanilla JS/CSS (no build step), pydantic v2.
Libraries (all verified on PyPI 2026-11-15): `anthropic` (LLM), `fastapi`, `uvicorn[standard]`, `pydantic`, `jinja2`, `python-multipart`, `python-dotenv`, `pytest` + `httpx` (tests use FastAPI `TestClient`).
Use the Anthropic SDK directly (model default `claude-sonnet-5-5`, override via `ANTHROPIC_MODEL`). No LangChain.

## Data model (SQLite, `app/schema.sql`, created on startup if missing)
- `practice` — single row: name, phone, address, hours_json (per weekday open/close), parking, what_to_bring, accepted_payers_json, faq_json.
- `providers(id, name, role 'dentist'|'hygienist', color)`
- `operatories(id, name)` — 4 chairs.
- `patients(id, first_name, last_name, dob, phone, email, preferred_hygienist_id, notes, created_at)`
- `appointments(id, patient_id, provider_id, operatory_id, start_at, end_at, type 'hygiene'|'exam'|'emergency'|'followup'|'consult', status 'scheduled'|'completed'|'cancelled'|'no_show', source 'staff'|'ai_inbound'|'ai_recall', created_at)`
- `insurance_plans(id, patient_id, payer, member_id, group_no, status, plan_name, in_network, annual_max, remaining_max, coverage_json, flags_json, verified_at)`
- `payer_directory(payer, member_id, dob, status, plan_name, in_network, annual_max, remaining_max, coverage_json, notes)` — the mock "clearinghouse".
- `conversations(id, channel 'inbound'|'recall', patient_id, started_at, ended_at, outcome, mode 'mock'|'live', messages_json, tool_log_json)`
- `recall_outreach(id, patient_id, conversation_id, message, proposed_slots_json, sent_at, status 'sent'|'replied'|'booked'|'declined'|'snoozed')`
- `messages_taken(id, conversation_id, patient_name, phone, summary, created_at, done)`

**Seed** (`app/seed.py`, also `POST /api/demo/reset`): fictional practice "Maple Street Dental" (hours Mon–Fri 8:00–17:00, Sat 9:00–13:00), 2 dentists + 2 hygienists, 4 chairs, ~30 patients with phones/DOBs, ~60% of slots for the next 10 business days pre-booked by `staff`, a history of completed appointments so that **at least 8 patients are overdue**, insurance plans for ~20 patients with matching rows in `payer_directory` (include at least one inactive member, one out-of-network, one low remaining max). Seed dates are generated relative to today so the demo never goes stale. Seed must be idempotent (reset drops and recreates).

## Agent / LLM design (`app/agent.py`, `app/llm.py`, `app/tools.py`)
- **Tools** (Anthropic tool definitions, `strict: true`, `additionalProperties: false`, executed against SQLite):
  `find_patient(first_name, last_name, dob)`, `create_patient(first_name, last_name, dob, phone)`, `get_patient_appointments(patient_id)`, `get_availability(date_from, date_to, appointment_type, provider_id?)` → up to 10 open slots (chair + provider free), `book_appointment(patient_id, start_at, appointment_type, provider_id, operatory_id)`, `reschedule_appointment(appointment_id, new_start_at)`, `cancel_appointment(appointment_id)`, `verify_insurance(patient_id?, payer, member_id, dob)`, `get_practice_info(topic)`, `take_message(patient_name, phone, summary)`, `end_call(outcome, summary)`.
- **Live mode**: manual tool-use loop with `client.messages.create(model, max_tokens=2048, system=..., tools=..., messages=...)`; do not use `tool_choice` other than the default `auto`; loop until `stop_reason == "end_turn"` or 8 iterations; all tool results for one assistant turn go back in ONE user message. System prompt includes the practice profile, today's date/time, the channel (inbound call vs recall text), hard rules (identify with name + DOB before any booking change; offer ≤3 slots; confirm before booking; never clinical advice; no cost promises; if stuck → take_message; keep replies to 1–3 short sentences, spoken style). Conversation `messages_json` persists the full message list including tool blocks so multi-turn works across HTTP requests.
- **Mock mode** (`MOCK_LLM=1` or no `ANTHROPIC_API_KEY`): a deterministic scripted receptionist in `app/mock_agent.py` that drives the **same tools**: state machine `greet → ask_identity → (find/create patient) → ask_reason → offer_slots → confirm → booked`, with intent detection by keywords/regex for `reschedule`, `cancel`, `insurance`, hours/address/parking FAQs, and "speak to a person" → take_message. Recall replies: "yes/works/book/the first one/tuesday" → book proposed slot; "no/stop/not interested" → declined; "later/next month/call back" → snoozed. Recall outreach text in mock mode is templated. UI shows a "MOCK MODE" badge when active. Every flow must work end to end in mock mode.
- Env (`.env.example`): `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL=claude-sonnet-5-5`, `MOCK_LLM`, `DATABASE_PATH=./chairfill.db`, `RECALL_MONTHS=6`, `PORT=8000`.
