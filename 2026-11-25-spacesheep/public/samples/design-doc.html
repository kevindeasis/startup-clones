Notification Service Design

This document describes the architecture of the notification service, which delivers email, push and in-app messages to customers. The service must handle bursts of traffic during product launches without dropping messages.

Goals

  • Deliver ninety nine percent of messages within five seconds.
  • Support retries with exponential backoff for transient provider failures.
  • Expose a single publish API for every internal team.

Architecture

Producers publish events to a queue. A fleet of workers renders templates, applies user preferences and hands messages to channel adapters. Each adapter is responsible for one provider.

producer -> queue -> worker -> adapter -> provider
Reliability matters more than latency for transactional messages.

Open questions

Should we build our own rate limiter or adopt an existing library? We lean toward adopting one.
