# Proven: an Axiomat clone

> Independent learning clone. Not affiliated with, endorsed by, or derived from the code of Axiomat or Y Combinator.

## What the original does

[Axiomat](https://www.axiomat.com) (YC F26, [launch post](https://www.ycombinator.com/launches/X3M-axiomat-agents-that-cannot-hallucinate)) is a data layer that lets AI agents answer questions about business data without hallucinating. A company's business rules become formal definitions. When an agent writes a query, Axiomat proves in Lean that the query matches the definition. If it can't be proven, the query doesn't run, and the agent retries or reports that it found no answer. Before answering, the user sees how the question was understood, restated in English generated by code, not by the AI.

## What this clone does

Proven keeps the product shape and swaps Lean for a deterministic semantic-layer verifier:

1. **Ask**: the LLM only emits a structured *interpretation* (metric, group-by, filters, time range). Code compiles it to SQL from `rules.yaml` and writes the English restatement from templates.
2. **Verify**: 7 checks must pass (`parses`, `allowed_tables_columns`, `metric_expression_matches`, `required_predicates_present`, `group_by_consistent`, `invariants_hold`, `executes`). Failing queries are never run against the user-visible path.
3. **Retry loop**: exact failure strings go back to the LLM, up to 3 attempts. If all fail, the answer is "I couldn't find a proven answer" with reasons and no numbers.
4. **Rules / Schema tabs** and a **Verify SQL** tab (`POST /api/verify`) for agent integration.

Skipped: real Lean proofs, auth, billing, multi-tenant, external warehouses, docs ingestion (rules are hand-written YAML), streaming, conversation memory.

## Architecture

```
question -> llm.py (Claude via client.messages.parse, or mock_llm.py)
         -> Interpretation (pydantic)
         -> compiler.py  -> SQL + English restatement (code only)
         -> verifier.py  -> 7 checks (sqlglot AST + DuckDB invariants)
         -> pass: run + show / fail: feed failures back (max 3 attempts)
```

- `rules.yaml` is the semantic layer: tables/columns, 6 dimensions, 7 metrics, 6 invariants.
- `data/seed.sql` builds a deterministic B2B SaaS dataset with traps (trials, churn, invoice-line double counting, refunds). DuckDB file `data/proven.duckdb` is recreated at startup (gitignored) and reopened read-only; use `PROVEN_DB_PATH=:memory:` for in-memory.
- `app/static/index.html` is a no-build vanilla SPA.
- Note on the retry demo: the compiler lets a user filter override a required predicate on the same column (deliberately naive). In mock mode, "including trials" first filters `is_trial = true`, the verifier rejects the missing `is_trial = false` predicate, and attempt 2 drops the filter. The final answer therefore still excludes trials, and the restatement says so.

## Setup and run

```bash
cd 2026-11-26-axiomat
uv venv .venv && uv pip install -r requirements.txt      # or: uv pip install -e .
# fallback: python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # optional; export the variables, the app does not auto-load .env
.venv/bin/python -m uvicorn app.main:app --port 8000
# open http://localhost:8000
```

Tests: `.venv/bin/python -m pytest` (28 tests). API smoke test (boots a server in mock mode, curls it): `./scripts/smoke.sh`.

Live mode: `export ANTHROPIC_API_KEY=...` (and unset `PROVEN_MOCK`). The UI badge shows MOCK MODE or the model name.

## Environment variables

| Variable | Default | Meaning |
|---|---|---|
| `ANTHROPIC_API_KEY` | unset | Absent means mock mode |
| `ANTHROPIC_MODEL` | `claude-opus-5-5` | Model for the interpretation step |
| `PROVEN_MOCK` | unset | Set to `1` to force mock mode even with a key |
| `PROVEN_DB_PATH` | `data/proven.duckdb` | DuckDB file or `:memory:` |
| `PORT` | `8000` | Port to pass to uvicorn (`--port $PORT`) |

## Known limitations

- Live (Claude) mode is implemented per the SDK but was **not exercised** here (no API key in the build sandbox). Only the error path is unit-tested with a fake client.
- Verification is syntactic AST equality plus invariants, not a proof; semantically equivalent but differently written aggregates are rejected, and invariants are coarse upper/lower bounds.
- The verifier rejects any WHERE conjunct that is not a required predicate, a dimension-vs-literal comparison, or a date-column bound, and any nested SELECT/UNION, so valid-but-exotic SQL is refused. Mock interpreter is keyword-based and handles only the example-style questions.
- With `:memory:` the connection is not physically read-only (verifier gating only).
- UI layout was written for phone width but not checked in a real browser during the build.
